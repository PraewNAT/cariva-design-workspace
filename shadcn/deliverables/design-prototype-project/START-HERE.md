# ส่งให้ AI อีกตัว

ชุดนี้เป็น instructions สำหรับปรับใช้ในโปรเจกต์ที่มีอยู่หรือโปรเจกต์ใหม่ ไม่ได้ติดตั้ง DS, skills หรือ Figma MCP และไม่มีโค้ด/สี/ฟอนต์/URL ของบริษัทต้นทาง

## ข้อความที่คัดลอกส่งได้

> อ่าน README.md, rules/project-guide.md และ rules/workflow-map.md ในชุดนี้ก่อน โปรเจกต์ของฉันอาจมีโค้ด DS และกฎเดิมอยู่แล้ว ให้ตรวจสิ่งที่มีและเสนอการ merge กฎโดยรักษาคำสั่งเดิม ไม่เขียนทับไฟล์ทั้งก้อน เป้าหมายคือใช้ AI ประกอบเว็บ prototype จาก component ที่มี เพื่อกดทดสอบและดู responsive เมื่อฉันอนุมัติและสั่งจึงประกอบ editable frames ใน Figma ด้วย component จาก DS และเมื่อฉันส่งดีไซน์ Figma มาให้ implement ให้ใช้ component โค้ดเดิมก่อน ไกด์ฉันทีละขั้น ถามเฉพาะข้อมูลที่ขาด ตรวจเครื่องมือที่เข้าถึงได้จริง และไม่สร้าง component ทั้งชุดล่วงหน้า

## ข้อมูลที่ฉันแนบเพิ่ม

```yaml
ชื่อ Product:
Figma DS กลาง URL:
Figma DS Product URL: ใช้ของกลางอย่างเดียว / ยังไม่มี / URL
Figma ไฟล์ออกแบบหน้าจอ URL: ยังไม่มี / URL
```

- ให้ AI เข้าถึง repository/โฟลเดอร์จริง หรือแนบ package.json และโครงสร้างไฟล์ถ้ายังเข้าถึงไม่ได้
- แนบ DESIGN.md และ AGENTS.md / CLAUDE.md / กฎเดิมที่มี ห้ามแทนที่ด้วย template อัตโนมัติ
- แนบ Storybook URL หรือรายการ component/docs ที่มี ถ้าทราบ
- บอกงานที่ต้องการเริ่มและข้อห้ามที่รู้แล้วได้ทันที AI ต้องจำไว้ ไม่ถามซ้ำตอน setup จบ

## สิ่งที่ AI ต้องทำก่อนเริ่ม UI

1. สรุป objective และความต่างกับกฎเดิม แจ้งข้อขัดแย้ง
2. อ่าน Product records ถามเฉพาะช่องที่ยังขาดและเก็บแยก Product
3. ตรวจ code base (เช่น MUI/shadcn/Ant/custom), tokens, docs, Storybook, skills และ Figma access จากหลักฐานจริง
4. เตรียมเฉพาะโครงที่ขาดและสรุป readiness ก่อนถามหน้าจอแรกเป็นขั้นสุดท้ายของ setup
5. วางเคสและ reuse แล้ว implement/test/document/audit ตาม scope

หากต้องการ Canvas ให้หลายหน้า/หลายเคสเรียงพร้อมเส้น flow และซูม/เลื่อนได้ โดยไม่ต้องมี panel แก้ดีไซน์ ส่วนกฎด้านสี ฟอนต์ ขนาด และ geometry ให้อ่านจาก DS บริษัทปลายทาง

## ส่งงานกลับระหว่าง AI

ใช้ TASK-HANDOFF.md กรอกสถานะจริง ไม่ส่ง credentials หรืออ้างว่าเครื่องมือของอีกตัวติดตั้งพร้อมแล้ว

## วิธีให้ AI ทำตาม flow

ให้เริ่มด้วยระบุชื่อ flow และรหัสขั้นปัจจุบัน ใช้ตารางเป็นเกณฑ์ผ่านแต่ละขั้น ถ้าข้ามขั้นให้ระบุหลักฐานว่างานนั้นมีอยู่แล้ว ไม่แปล “มีเอกสาร” เป็น “implement/test แล้ว” แสดง Mermaid เมื่ออธิบายภาพรวมและเก็บผลจริงใน handoff
