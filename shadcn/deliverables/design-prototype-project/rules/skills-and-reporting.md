# Skills and reporting

This template contains workflow instructions, not third-party skill installations. Discover actual session/project skills and their paths before use. Read applicable SKILL.md files; never assume a command, framework or connector exists in both assistants.

| Concern | Capability to locate |
|---|---|
| Requirements/cases | case planning |
| Existing DS and duplicates | component reuse check |
| Implementation | skill/docs for the selected base, not always shadcn |
| Visual craft | installed UI design/polish skill compatible with company rules |
| Stories/source/tests/review | tooling matching installed Storybook/stack |
| Component documentation | documentation skill using real code and approved specs |
| Rendered quality | component audit |
| Figma work | official installed skills for read/write, libraries or screens |
| Diagrams | installed Mermaid skill when diagrams are requested |

Reuse one workflow per concern. If a skill/tool is missing, report it and continue independent work using available commands and written rules; do not claim the missing step ran. Propose installation when needed; do not copy host paths or credentials from another workspace. Tool permissions remain applicable.

## Concise report contract

Use these fields in order for reuse, case and audit reports; keep detailed evidence in task files, not a long chat log.

```text
[Concern] — [Product / scope]
ผลรวม: [outcome]
ขอบเขต: [actual targets and limitations]

| ระดับ | ผล | รายการ | หลักฐาน | ถัดไป |
|---|---|---|---|---|
| [สูง/กลาง/ต่ำ/—] | [status] | [finding] | [real file/story/test] | [action] |

สรุป: [counts including unresolved checks]
ต่อไป: [next action or none]
```

Audit/reuse statuses: ผ่าน / ต้องแก้ / ตรวจไม่ได้. Case statuses: ยืนยันแล้ว / เสนอเพิ่ม / ต้องถาม, with implementation coverage separately identified. Never invent URLs, node IDs or passing results; never call a mixed result fully passed. Follow installed tooling's required review-link output where applicable.
